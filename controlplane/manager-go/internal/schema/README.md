# 数据库迁移模块

本包只负责结构升级，不依赖 `main` 包的动态业务对象、密钥、任务和执行服务。`Apply(ctx, db, prefix)` 使用内嵌的冻结目录；`Run` 使用相同执行器，供隔离验收使用显式目录。

## 现有目录

1. `001_initial_tables.json`：承接此前启动时的 27 个表。空库创建，既有库通过 `IF NOT EXISTS` 采用现有表。
2. `002_projects_and_indexes.json`：承接默认项目列、项目索引、任务列表索引及诊断索引。仅缺失项目列使用 `project-default`；不重写旧 JSON 或密文。
3. `003_report_projections.json`：补齐旧报告及子表的类型投影。仅首次计划中缺失的列从 `data` JSON 回填；已有列值保持原样。缺少计数使用 0，缺少浮点指标使用 NULL，缺少验收结论使用 `NOT_SET`。文本投影受目标列长度约束，原 JSON 字节不变。旧来源 `key` 和指标 `key` 分别兼容到 `object_key`、`metric_key`。
4. `004_page_read_models.json`：增加工作区/版本/脚本摘要、CSV节点投影、报告分析范围表、不可变脚本图缓存、任务及报告生成列和查询索引。DDL不重写原工作区密文。管理端CLI `rebuild-read-models` 分批回填业务读模型，可中断后重跑；旧报告保留原分析数据，并记录范围投影已建立。CSV投影和脚本缓存可重建，报告范围表随逻辑备份保存。
5. `005_workflow_editor_read.json`：补齐工作区编辑视图缓存列，不改写原 authored payload。
6. `006_plan_library_state.json`：新增独立脚本目录归档状态表及项目/归档索引，补齐脚本项目/序号分页索引。既有脚本无状态行时均可见，不回填、不更新不可变脚本或任务。状态表随逻辑备份保存，旧备份缺此表时按空表导入。
7. `007_query_indexes.json`：为数据集的项目列表、流程列表及报告的项目列表增加分页排序索引。只增加索引，不新增字段、不改写 JSON、密文、不可变版本或逻辑备份格式；报告按创建时间、版本、ID 倒序稳定分页。
8. `008_history_deletion.json`：新增任务删除墓碑 `deleted_runs` 与带租约、重试进度的制品清理队列 `artifact_cleanups`。业务记录删除与外部制品清理解耦，不依赖同步删除远端文件。

9. `009_extension_registry.json`：独立扩展目录与不可变定义版本，项目/种类独立revision。
10. `010_monitoring_evidence.json`：报告监控修订、不可变去重证据与修订成员，SQL筛选分页。

业务写入字段定义仍由各领域维护，迁移文件描述已发布的数据库历史，不能随领域字段定义自动变化。后续字段变更必须新增连续编号的迁移，而不是修改上述文件。

## 执行和恢复

每个 MySQL 实例内，按数据库名和表前缀派生命名锁。获取、DDL、回填、账本更新和释放都使用同一个专用连接，不另外占用连接池；单连接池也可执行。前缀只允许字母、数字、下划线，最多 40 字符，迁移表/列/索引标识符由受控定义提供。

`schema_migrations` 保存 `version/name/checksum/state/plan/applied_at`。检查整个历史连续性及定义校验和后，先记录 `APPLYING` 和原始缺列计划，再执行 DDL/回填，最后记录 `APPLIED`。MySQL DDL 会隐式提交，本模块不假设 DDL 可被事务回滚。失败后的物理列可能已经存在，恢复仍使用原始计划完成回填；不能重新计算缺列而漏掉这一步。已完成的版本不会再次执行。

连接中断或锁获取/释放结果不确定时，丢弃物理连接，避免持锁连接返回池。锁等待遵守 Context；启动总迁移期限 5 分钟，单条 MySQL 操作还受 `JMETER_MYSQL_TIMEOUT` 限制（默认 15 秒）。通过 supervisor 启动时，还受 `JMETER_WATCHDOG_TIMEOUT` 的首次心跳预算限制（默认 90 秒）；大库升级需同步评估该预算和单条操作超时，不在真实压测过程中升级。需要初始化 Platform 的备份/导入导出 CLI 也会先执行迁移；`db-check` 仍仅检查数据库连接。

失败时管理端拒绝启动，不暴露半升级实例。日志只输出迁移版本、阶段和错误类型。恢复依赖、权限或资源后可使用相同版本重启继续；不要删除账本绕过错误。定义校验和不一致、未知未来版本、缺失前序或不合法计划均拒绝执行。该检测只保护采用本模块的版本，不能让历史上尚未使用账本的旧二进制自动识别降级。

## 后续迁移

新增 `migrations/011_<name>.json`，使用明确的 `Migration/Column/Index` 字段。编号必须连续；JSON 外层排版不影响校验和，SQL/列/索引定义改变会影响校验和。声明式补列和索引按元数据判断是否已执行。额外 `statements` 必须可在 DDL 部分成功后安全重试；不要放一次性累加或外部 I/O。类型变更、删列及大规模数据重整需要单独设计相应操作和恢复验收。

`004` 与 `006` 分别声明的脚本项目/序号索引目前保留两份。历史迁移不能改写；删除重复索引留待支持条件判断及安全重试的独立维护迁移，本轮不增加删索引操作。

`backfill` 只用于新加入的投影，必须处理无效/缺少/null JSON 值，不能修改 `data` 或加密 payload。新字段同时维护业务读写/备份字段，以及空库、旧库和部分成功后重试的集成回归。

## 备份与回滚

账本不属于逻辑业务导出，不加入 `portableTables`。恢复到空库时，当前二进制先运行自身迁移，再导入既有格式的业务数据。物理数据库备份包含账本，需与对应迁移定义一同保留。本模块不执行降级或自动撤销 DDL；需要回退时使用匹配版本的备份与二进制。
