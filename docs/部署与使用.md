# PressureCooker 部署与使用

PressureCooker 是通用压测管理平台。自研管理端、CLI、MCP 适配和执行器使用 Go，前端使用 Vue；JMeter、Scalar、LogicFlow 和指定 npm MCP 使用各自官方运行时。项目接口、数据准备和业务断言由使用者在接口集合、环境、数据集和脚本中配置。

## 架构与部署配置

管理端提供页面、API、项目资源、任务队列和结构化报告，MySQL 保存元数据及加密内容，Redis Streams 传递执行任务，MinIO 保存脚本、数据集和原始结果。控制器与执行节点使用相同 JMeter/Java 运行时。默认 Compose 配置提供两个 PressureCooker-Core 和六个 worker，初始分配为2个与4个worker，平台全局一次执行一个批次；每个所选节点执行完整 JMX。

同一宿主机的多个容器共享该主机资源，不能作为多台物理机容量计算。线程数、运行时长和超时是否生效取决于所发布的脚本是否引用相应参数。

部署参数见 [cluster.env.example](../cluster.env.example) 和 [compose.yaml](../compose.yaml)。按目标主机配置 MySQL、Redis、MinIO、监听地址和端口，凭据使用 `runtime/` 下的私有文件。页面与 API 默认端口为18090，MCP为18091，MinIO API及控制台为19000/19001；开放范围由实际部署的网络与反向代理决定。

新安装默认使用 `COMPOSE_PROJECT_NAME=pressurecooker` 和通用镜像名称。升级既有实例前，须在其 `cluster.env` 显式保留原 `COMPOSE_PROJECT_NAME`，再替换源码配置。现有远端实例仍位于 `/home/yanww/pressure/jmeter`，Compose 项目标识仍为 `walmart-jmeter`，其配置须显式设置 `COMPOSE_PROJECT_NAME=walmart-jmeter`。已有镜像标签和部署标识是该实例的运维契约；源码目录改名或业务测试资产外移不会迁移其数据、卷、对象键或运行资源。

新保存的大流程在压缩明显有效时使用快速 gzip 无损压缩后再以 AES-GCM 加密（`gcm2:`），减少当前稿和历史版本的数据库写入量。旧 `gcm1:` 密文继续可读，不自动重写历史；接口集合、环境和任务仍保持原格式。新格式将压缩方式与表、ID、版本一起认证，解压有独立容量上限。生成过 `gcm2:` 流程的数据库和备份须使用支持该格式的管理端；回退功能时也须保留该读取能力，不能直接换回不认识新格式的旧二进制。恢复仍须保留原 `session-key`。

## 本地构建与验收

构建需要 Go 1.25.5+、Node 22.12+、JDK21 和官方 Apache JMeter 5.6.3 分发包。依赖与源码校验记录保存在 `vendor/`；新发布必须由当前源码重新构建。

```bash
cd controlplane/frontend
npm ci
npm run build
cd ../..
bash bin/prepare-mcp-cache.sh
GO=/path/to/go JAVA_HOME=/path/to/jdk21 JMETER_HOME=/path/to/apache-jmeter-5.6.3 bash bin/build-master.sh
```

`build-master.sh` 同时编译管理端、MCP、执行器、平台工具和官方 JMeter 线程观测 Listener，并生成产物及源码校验值。Listener 必须装入控制器及所有执行节点的 `JMETER_HOME/lib/ext/`；Docker 构建会使用当前构建产物。

全新部署还需准备 Docker 构建所用的官方 JMeter 归档 `vendor/apache-jmeter-5.6.3.tgz`，并用相邻的 `.sha512` 文件校验。Node 归档由 `manage.sh build` 调用的 `bin/fetch-node.sh` 按锁定版本和 SHA256 准备。

MinIO 镜像另外需要 `vendor/minio-linux-amd64`，`build-master.sh` 不生成它。在 Linux amd64 构建主机执行下列命令，使用锁定的官方源码与 Go 工具链构建：

```bash
bash bin/build-minio.sh
```

该脚本的构建缓存保存在 `runtime/minio-build/`。macOS 可以执行平台本地测试与前端/Go 交叉构建；MinIO 的此构建入口要求 Linux amd64。已有实例升级沿用其显式镜像及持久数据，是否替换 MinIO 应单独决定。

常规验收使用 `GO=/path/to/go bin/test-controlplane.sh`，涵盖三个 Go 模块、平台工具、前端测试和生产构建。隔离数据库验收与本机 WebSocket 夹具说明见 [测试基线与验收](测试基线与验收.md)。构建和测试不要求任何具体业务项目或外部业务脚本。

## 启动与检查

先核对目标目录中的 `cluster.env`、依赖、凭据文件和持久卷。MySQL、Redis 需要预先可达，分别在 `runtime/secrets/platform/mysql-password`、`redis-password` 写入与实际服务匹配的私有密码文件；自动凭据准备不会创建这两个外部服务密码。其他平台密钥只在缺失时创建，已有值保留。再执行所需管理命令：

```bash
./manage.sh config
./manage.sh build
./manage.sh init
./manage.sh up
./manage.sh ps
./manage.sh logs manager
```

`/healthz` 检查管理进程存活；`/readyz` 检查 MySQL、Redis 和管理循环进度。平台登录、API及MCP使用已配置的管理凭据，不在文档或运行日志中保存凭据正文。

## 项目资源与任务

先选择项目，再维护项目环境、接口集合、流程和数据集。环境提供 `base_host` 和自定义变量；任务提交时必须明确选择环境和集群，固定脚本版本、节点集合、环境版本、超时及数据分配快照。

保存草稿、预览和发布脚本都不会自动执行。创建任务时，检查目标地址、每节点负载、数据集分配、超时及验收目标。通过 MCP 提交使用 `submit_console_task`，并提供 `projectId`、`clusterId`、`environmentId`、`managerPlanId` 和稳定的 `idempotencyKey`；同一提交的重试保持键及请求一致。完整说明见 [MCP 接入](../controlplane/mcp-go/README.md)。

CLI 通过同一管理 API 操作：

```bash
./manage.sh api cluster
./manage.sh api upload plans/example.jmx --project PROJECT_ID --name 示例计划
./manage.sh api start PLAN_ID --project PROJECT_ID --cluster CLUSTER_ID --environment ENVIRONMENT_ID --name 本轮任务 --property threads=1 --key UNIQUE_RUN_KEY
./manage.sh api run RUN_ID --project PROJECT_ID
./manage.sh api stop RUN_ID --project PROJECT_ID --mode graceful
```

数据集在任务快照中绑定到具体 CSV 节点，可选择 copy 或 shard；实际文件随任务传入执行节点。通用 CSV 请求体示例见 [csv-post-json-v1](../examples/csv-post-json-v1/README.md)。

## 原始文件、报告与恢复

任务结束后归档实际产生的 `results.jtl`、`jmeter.log`、`console.log`，并按执行能力保存节点日志、请求留样及独立线程观测。MinIO 归档校验大小和 SHA256，缺失、截断与失败明确记录。原件归档成功表示文件保存成功，脚本中的业务断言和报告目标另行决定验收结论。

结构化报告由后台作业解析已归档原件，支持固定版本、重新解析、对比、节点和步骤筛选、实际留样及离线 HTML。报告口径和 API 以 [PRESSURE-REPORTS.md](../PRESSURE-REPORTS.md) 为准。读取报告不会提交压测。

任务与历史、压测报告列表支持单条删除、勾选当前页批量删除及当前项目一键清空，均需确认。清空忽略筛选和分页；任务只删除已结束记录并级联关联报告和产物，未结束任务保留。报告独立删除会保留任务与原始文件。归档项目只读。数据库记录事务删除，物理产物延迟清理并在存储故障时重试；页面删除后不能恢复，已有备份按恢复流程使用。 该功能通过版本 8 迁移新增删除标记和清理意图表，不重写既有任务或资源载荷。需要远端清理但对象存储配置暂缺时，意图保留并重试；本地备份恢复仍须保持原 `session-key`。

正常停止先请求 JMeter Shutdown，必要时终止该次进程并复位节点。控制器故障后的清理与恢复遵循任务/尝试/节点代次校验；中断任务不承诺无损续跑，也不通过重复提交替代恢复。

备份包括 MySQL 元数据、发布内容及本地状态，MinIO 对象、执行器待确认状态、MCP 草稿与归属索引需按各自持久卷单独保留。必须安全保留原 `session-key`，否则旧环境、集合和流程密文无法解密。

```bash
./manage.sh backup /backup/snapshot-new
./manage.sh restore /backup/snapshot-new /restore/empty-target
```

恢复目标必须是独立空目录/数据库。恢复后从认证接口下载代表性脚本、数据集和原始结果，核对收据中的长度与 SHA256，再开放任务提交；历史归档状态不能代替当前对象可用性验证。

## 内部自测

部署验收可显式运行 `./manage.sh smoke PROJECT_ID CLUSTER_ID ENVIRONMENT_ID`。它临时启动内部 HTTP `smoke-target`，在所选已登记集群的全部节点执行通用自测计划，每节点校验五条成功样本并检查原始文件，结束后关闭目标。它不读取业务资产，也不访问真实业务系统。日常源码构建与测试不要求运行此部署自测。

界面操作见 [流程画布与接口管理](流程画布与接口管理.md) 和 [项目与接口复用](项目与接口复用.md)。

## 节点注册与状态

Core连接Redis并确认消费组后，向 `PRESSURECOOKER_MANAGER_URL` 主动注册，随后每5秒汇总worker状态及机器指标。管理平台不再向Core或worker发起节点状态查询；缺报和超时不会被容器运行状态替代。上报、显示、恢复栅栏及部署配置见[节点注册与状态](节点注册与状态.md)。

## 测试期结构收敛与显式转换

当前 schema 为10。迁移009建立项目/种类独立的扩展目录和不可变定义版本；首次启动按32项目一批从旧项目 JSON 复制目录，不改写原项目 JSON，后续读写仅使用独立目录。迁移010建立监控修订、去重证据和修订成员表；旧监控须显式转换，普通读取返回 `monitoring_conversion_required`。001–008 的定义和校验和保持冻结。

所有项目资源 API 须给 `X-Project-ID`，CLI 资源命令须给 `--project`；原生下载可显式使用 `project_id` 查询参数。历史 HTML 入口跳转到 `/api/projects/{project_id}/reports/{id}/html/{path}`，相对资源沿路径保留项目归属，仍逐请求鉴权和核对所有权，不改写原文件。项目列表、会话、平台集群和工具发现属于平台级入口。诊断积压按项目查询，必须提供 `X-Project-ID`；进程计数仍为平台共享。历史文件导入使用 `import-history DIRECTORY --project PROJECT_ID`，目标必须存在且未归档。缺省项目不再隐式补齐。控制器必须由部署的 `PRESSURECOOKER_CLUSTER_WORKERS` 或已保存集群配置明确成员；无映射显示待配置，不能自动继承所有节点。Compose 的2/4映射是部署参数，不是核心默认规则。

旧 HTTP 调度、自动归档轮询及无任务归属的重置已退出。历史任务可继续读取、导出，旧非终态不会阻塞当前 Redis 队列。处理旧元数据的步骤为：

```bash
pressurecooker-manager retired-executions
pressurecooker-manager retire-execution RUN_ID --fingerprint AUDITED_SHA256
pressurecooker-manager convert-monitoring
pressurecooker-manager rebuild-read-models
```

命令沿用目标实例的显式数据库、Redis和凭据文件配置；请使用实际构建产物路径。退役须持有全局租约，并取得该租约 observation epoch 下全部配置 worker 的健康空闲证据，随后锁定任务和指纹，只将该旧记录明确置为 `INTERRUPTED` 并写一次审计。不自动清理远端、不重派任务；节点未上报或仍忙则拒绝。相同原指纹重复操作幂等。

`convert-monitoring` 按32条keyset扫描，在每条事务中保留原快照字节及SHA，拆分后重组核对；中断可重入，内容冲突拒绝。新写入只使用新表，不双写旧快照。备份包含新表；恢复校验证据哈希、报告/项目/修订归属、摘要和幂等回执、成员引用及转换源指纹，仍必须保留原 `session-key` 和单独备份的MinIO对象。数据集旧投影缺失或缺列来源标记时，仅回读对应流程，运行 `rebuild-read-models` 可更新派生缓存而不改历史源码。

监控 HTTP 读取默认服务端分页20条；`revision` 不关闭分页。仅 `export=1` 显式全量读取，可与 `revision` 同用，不能与筛选分页混用。MCP 按页读取；离线HTML导出仍包含完整选定版本。
