# 测试基线与验收

默认验收不依赖数据库或平台凭据，按顺序执行 Go 三模块测试、Vue 全量测试和生产构建：

```bash
GO=/path/to/go bin/test-controlplane.sh
```

需要 Go 1.25.5+、Node 22.12+，以及已经安装的前端和官方 npm MCP 依赖。入口会先检查 Node 和官方 MCP 入口文件，依赖缺失时直接失败，避免真实工具目录测试被跳过后误报成功。前端测试同时最多运行两个 worker，避免 Scalar 等依赖的并行初始化耗尽资源而误报超时。默认命令显式关闭外部集成测试，即使调用者环境中曾开启这些开关。

平台测试只依赖仓库内的通用夹具。容量测试在内存生成超过1500节点、31线程组及33个CSV绑定的大图，继续验证超过5MiB的编译、持久化和不可变发布边界。它不读取业务脚本库或外部场景生成器。

WebSocket运行时可显式使用官方本机JMeter和JDK执行合成JSON协议夹具：

```bash
cd controlplane/manager-go
JMETER_HOME=/path/to/apache-jmeter-5.6.3 JAVA_HOME=/path/to/jdk21 \
  go test -count=1 -run '^TestWorkflowWebSocketTraceThreeTurnDialogue$' .
```

夹具仅连接测试进程的本机随机端口，覆盖三轮独立消息ID、重复与带引号/换行的CSV内容、提前到达回复、拒绝/缺失/过期确认、错误回复、超时、连接清理及日志脱敏。业务协议和真实环境验收在对应业务工作区维护，不属于平台基线。

## 隔离集成验收

准备本机临时 MySQL、Redis 和 MinIO，使用测试凭据文件。MySQL 主机仅允许 `localhost` 或 `127.0.0.1`，数据库名必须以 `pressurecooker_test` 开头；Redis 仅允许 `127.0.0.1:26379` 或 `localhost:26379`。入口拒绝远端依赖和其他 Redis 端口；测试只操作随机前缀的表，并在结束时清理。

通过一个仅保存在 `runtime/` 中的环境文件配置以下变量，再运行：

```bash
source runtime/test-env.sh
GO=/path/to/go bin/test-controlplane.sh --integration
```

- MySQL：`JMETER_MYSQL_HOST`、`JMETER_MYSQL_PORT`、`JMETER_MYSQL_DATABASE`、`JMETER_MYSQL_USER`、`JMETER_MYSQL_PASSWORD_FILE`。
- 平台测试文件：`JMETER_ADMIN_TOKEN_FILE`、`JMETER_SESSION_KEY_FILE`、`JMETER_AGENT_TOKEN_FILE`。使用临时测试值，不使用线上密钥。
- 管理端 Redis：`JMETER_REDIS_ADDR=127.0.0.1:26379`、`JMETER_REDIS_PASSWORD_FILE`。
- 执行器集成夹具使用本机 Redis `26379` 和 MinIO `29000`，凭据从 `runtime/local-secrets/redis-password`、`minio-access-key`、`minio-secret-key` 读取；MinIO 需预建私有桶 `jmeter-reports`。
- 管理端的 HTTP、对象存储和 agent 交互使用测试进程内的模拟服务；历史调度用显式持久化的旧协议记录，当前任务按 Redis 签名快照验证。执行器用假 JVM 验证启动、停止和恢复，不请求业务压测目标。

统一入口不会启动管理端调度循环或真实 JMeter 集群，也不会部署、发布或修改远端配置。临时依赖容器由创建者在验收结束后清理。

## 工具目录契约

MCP 测试将实际 Go 适配器和官方 Node 进程返回的工具目录与前端夹具比较。新增参数时同步维护中文参数说明；只在确认真实工具变更后更新夹具：

```bash
cd controlplane/mcp-go
go test -run '^TestLiveToolCatalogMatchesFrontendFixture$' -update-mcp-fixture
```

更新后必须重新运行 MCP 和前端全量测试，不能通过跳过目录一致性或本地化断言来恢复绿灯。

## 任务列表回归口径

任务列表保持 `items`、`total`、`project_id` 与 `limit/offset`，项目及状态筛选先于 SQL 分页，按创建时间、ID 倒序排列。只解密当前页，报告、历史回调和投递状态批量读取，并复用详情的脱敏投影。

名称、ID、备注使用同一套 MySQL Unicode 5.2 小写规则进行字面子串匹配，区分重音；`%`、`_`、反斜杠不是通配符。回归覆盖中文、补充平面字母、旧记录的空/非字符串备注、空页、同时间排序、单连接池及本页之外的损坏密文。查询归一化以数据库规则为准，不依赖开发机 Go 的 Unicode 表版本。

首次启动会为新旧 `runs` 表补齐项目/时间与项目/状态/时间组合索引。索引补齐与重复启动通过隔离库验证，不改写历史任务 JSON 或密文。

## 前端静态资源缓存

- `/assets/` 下带构建指纹的文件使用 `public, max-age=31536000, immutable`，允许浏览器和共享缓存复用一年。文件内容变化必须发布新的指纹 URL；Vite 默认构建会生成这些名称。
- 入口 HTML（包括 SPA 路由回退）、其他 HTML 和不带指纹的公开静态文件使用 `no-cache`。服务器根据内容生成强 ETag；内容未变时，条件 GET/HEAD 返回 304，不重复传输文件正文。
- 校验不依赖文件大小或修改时间；即使入口文件大小和 mtime 相同，内容变化也会得到新的 ETag。HEAD、Range 和条件请求由 Go 标准库处理。
- API、认证下载与错误响应继续使用 `no-store`，不继承公开资源的 ETag 或长期缓存。不存在的指纹资源、非法路径以及 412/416 等条件请求错误也不可缓存。

定向验证无需数据库或执行器：

```bash
cd controlplane/manager-go
go test -run 'TestFrontend|TestPrivateFileDownloads' ./...
```

## 投递事务、取消与诊断

任务 outbox 继续使用 `PENDING/PUBLISHED/CANCELLED/FAILED`。领取时在短事务内增加 `attempts`，并把 `next_attempt_at` 设为 30 秒领取期限；事务提交后才向 Redis 发布，发布期限为 5 秒。确认只接受当前尝试版本，并重查任务终态。Redis 失败保存 `redis_unavailable`，按 1、2、4 秒递增，最多退避 64 秒；进程中断或确认失败的领取到期后可重新投递。消息可能重复送达，执行权限仍由 task/attempt 校验和独占引擎租约控制。停止与发布并发时，迟到消息不能执行已停止任务。

列表查询、会话认证、项目校验、投递和诊断使用带 Context 的数据库方法，保留测试表前缀隔离。客户端取消或超时会停止连接池等待、SQL 和事务重试；HTTP 错误分别使用 `499/request_cancelled`、`504/request_timeout`。

- `GET/HEAD /healthz` 保持进程存活检查，返回 200；已有容器重启策略无需更改。
- `GET/HEAD /readyz` 是免认证的就绪探针，共用 2 秒期限检查 MySQL、Redis，以及本进程 scheduler/dispatcher 的实际循环进度。全部正常返回 200，否则返回 503；只返回 `ok` 和受控状态，不回显地址或原始错误。循环尚未执行为 `starting`，最近执行失败为 `failed`，超过进度期限为 `stale`。dispatcher 期限 30 秒，scheduler 使用 watchdog 期限（至少 3 个 tick）。此探针不检查 MinIO 或业务压测目标。
- `GET /api/diagnostics` 使用现有认证及 `X-Project-ID`，返回该项目的投递积压/失败、最早积压时间和报告处理积压。`database_pool`、`loops`、`process` 为本进程共享信息；进程投递计数重启归零。诊断查询限时 2 秒，并为新旧表补齐项目/状态索引。
- 每个响应生成服务端 `X-Request-ID`，不采用调用方的同名值。错误日志按该 ID 记录方法、受控路由/错误码、异常类型、MySQL 错误号及耗时；投递日志记录任务 ID、尝试号和受控失败码。Redis 客户端内部告警统一为 `redis_client_warning`，避免其默认日志泄露连接地址和原始异常。请求头、查询参数、任务快照及凭据均不入日志。以上接口保持 `no-store`。

定向隔离验收覆盖慢 Redis 期间立即停止、并发领取、领取过期、迟到确认、未确认发布恢复、密文损坏、会话/列表取消、依赖故障、循环失联、认证/项目隔离及诊断索引重复迁移；不启动真实压测。执行器还使用无响应的本机 TCP 夹具验证 Redis Context 期限。

## 版本化数据库迁移

管理端的结构升级现由独立的 [schema 模块](../controlplane/manager-go/internal/schema/README.md) 执行，冻结目录依次采用现有表、补齐项目/索引、补齐报告投影。每个数据库/表前缀使用专用连接持有 MySQL 命名锁；不同前缀隔离，单连接池可运行。`schema_migrations` 记录版本、定义校验和、`APPLYING/APPLIED`、原始缺列计划及完成时间。

先记录计划，再执行 DDL 和历史 JSON 投影回填，成功后记录完成。部分 DDL 已提交但回填失败时，重启仍按原计划继续，不能因列已存在而跳过回填。已完成版本不会重放；未知版本、定义漂移和不连续历史会拒绝启动。迁移总期限上限 5 分钟，单条操作受 MySQL 连接超时设置约束；supervisor 启动还受首次心跳 watchdog 预算约束，大库升级需配套评估这些期限。

历史 READY JSON、工作区密文、任务/attempt 标识及已有类型投影保持原样。仅新增的报告投影列从 JSON 补值，缺少计数为 0、缺少浮点指标为 NULL。逻辑业务导出保持当前格式，不携带迁移账本；空库恢复先运行当前迁移再导入数据。迁移测试中的旧库夹具明确移除本测试随机前缀的账本来模拟未版本化旧库，生产环境不能借此绕过版本校验。

隔离回归覆盖空库/旧库/重复启动、双连接池并发只执行一次、单连接池、锁等待 50ms 取消、命名空间隔离、DDL 成功后回填取消及重试、历史 JSON/现有投影不变、校验和/未来版本/历史缺口拒绝、锁不确定时丢弃连接及错误脱敏。不启动调度循环或真实业务压测。

## JMeter 原生组件与画布扩展

原生目录生成器及默认值只依赖仓库锁定的官方发行包。可用本地 JDK 和解压后的同版本 JMeter 运行仅反序列化验收：

```bash
cd controlplane/manager-go
JMETER_NATIVE_TEST_HOME=/path/to/apache-jmeter-5.6.3 \
  go test -count=1 -run 'TestWorkflowNative|TestWorkflowExtension|TestWorkflowExpand' .
```

覆盖全部原生组件的配置编译、官方 SaveService 读取、属性保留、旧脚本兼容、保留子流程展开、组件来源及项目定义加密。隔离数据库测试 `TestMySQLWorkflowExtensionsLifecycleIsolationCASAndHTTP` 覆盖 API、项目隔离、归档只读和 revision 冲突。前端 `src/workflow/extensions.test.js` 覆盖来源筛选、通用属性树、显式选择、卸载回退、展开及异步上下文隔离。它们均不启动真实业务压测。
