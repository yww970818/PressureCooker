# JMeter 扩展管理与画布适配

在主导航“扩展管理”或流程画布工具栏打开目录。目录显示组件名称、JMX 元素名/Java 类名、版本、来源位置和适配方式，并支持搜索和来源筛选。

| 来源 | 含义 |
| --- | --- |
| JMeter 原生 | 仓库锁定的 Apache JMeter 5.6.3 官方发行包中的组件 |
| 平台自定义 | 平台通用 WebSocket 采样器及实际线程数观测扩展 |
| 项目自定义 | 当前项目创建的 JavaScript 画布适配器，可安装、卸载、修改或删除 |
| 外部自定义 | 已保存流程中使用、但不在原生/平台目录中的组件；在“当前流程引用的组件”中查看 |

“读取组件引用”按需扫描当前项目已保存的流程及保留的子流程，显示组件数量和所属流程；不扫描未保存草稿或历史发布版本，也不核验远端 worker 的 JAR 安装状态。原生身份来自官方发行包的类和别名目录，不通过 `org.apache` 等名称前缀猜测。

## 原生组件

目录覆盖 117 种原生 TestElement 组件。画布支持搜索、新建、导入、编辑、作用域连线和编译导出。测试计划、线程组、HTTP、循环/条件/事务、变量、CSV、断言等沿用专用表单；新增 JSR223 六类组件的脚本表单和固定吞吐量定时器表单。其他组件使用通用 JMeter 属性树，支持标量、集合、嵌套元素的新增、修改和删除；`objProp` 用完整对象属性 XML 编辑。

新组件使用官方构造器/GUI 生成的默认属性，业务目标、认证和消息仍由项目填写。属性树不是 JMeter Swing 界面的复制，数值与表达式按文本保存，组件必需的地址、文件及运行依赖仍须配置。录制器、可视化监听器等组件保留 JMeter 自身的运行边界，加入画布不代表拥有浏览器内录制或实时 Swing 展示能力。

导入后保留原始组件属性、未修改字段及外部组件的 hashTree。旧草稿中曾按未知组件保留的原生子流程，可点击“展开原生子流程”显式转换为画布节点；保留当前节点 ID、别名、启用状态和已编辑参数。展开后再保存才形成新修订。读取旧草稿或已发布内容不会批量转换历史 XML。

重新生成目录：

```bash
python3 tools/generate-jmeter-catalog.py
```

脚本校验 `vendor/apache-jmeter-5.6.3.tgz.sha512`，从官方 save 别名和具体 TestElement 类生成目录，并以本地 JDK 在 headless 模式读取默认属性；不会启动测试引擎。

## 自定义 JavaScript 适配器

1. 在当前项目点击“新增 JavaScript 适配器”。
2. 填写名称、组件类型、版本、源码仓库或维护文档地址。组件类型必须与 JMX 元素名完全一致，也可使用 JMX 中实际使用的完整 Java 类名。
3. 提供 `adapt(component)`，在本地预览中验证后保存。新适配器保存时安装到当前项目。
4. 在自定义节点的“画布适配器”中明确选择对应适配器，再编辑生成的字段。
5. 保存流程草稿并预览编译结果，确认后发布。

```javascript
function adapt(component) {
  return {
    title: component.type,
    fields: [
      { property: "endpoint", label: "目标地址", kind: "text", tag: "stringProp" },
      { property: "message", label: "消息正文", kind: "code", tag: "stringProp" },
      { property: "enabled", label: "启用功能", kind: "boolean", tag: "boolProp" }
    ]
  };
}
```

输入为 `{type, properties}`：`type` 是组件类型，`properties` 为顶层标量属性名到文本值的映射。返回 `{title, fields}`，最多 64 个不重复字段；`kind` 支持 `text/code/boolean`，`tag` 支持 `stringProp/boolProp/intProp/longProp/doubleProp`，省略为 `stringProp`。字段修改只更新对应顶层标量属性，保留根属性、其他参数和原有子流程。已有属性保持原来的 XML 类型。

代码只返回表单数据，在隔离 iframe 内的 Worker 执行，禁止联网，超时会终止；不能访问主页面、连接或发送接口。代码和可选创建模板各最多 60 KiB，整个定义最多 128 KiB，每项目最多 100 个适配器。解析失败时显示错误并保留原 XML；卸载或删除不删除已有流程参数及历史引用。

可选填写单个组件元素作为“组件 XML 模板”，例如：

```xml
<example.CustomSampler guiclass="example.CustomGui" testclass="example.CustomSampler" testname="自定义请求" enabled="true">
  <stringProp name="endpoint"></stringProp>
  <stringProp name="message"></stringProp>
</example.CustomSampler>
```

提供模板后，可在画布组件栏新建此组件；没有模板时先导入包含它的 JMX。适配器负责画布表单，执行器仍需要安装组件对应的 Java JAR 及依赖。页面中的“启用编辑”仅控制当前项目是否可选择此画布适配器，不分发 JAR。运行依赖单独显示“未验证”；当前没有可信目标节点能力采集，不宣称远端可执行。

定义按项目加密保存，目录仅返回来源等元数据，读取正文须认证。定义保存在独立目录与不可变版本库，同一ID/version改变内容返回 `extension_version_conflict`，必须增加version；新选择保存 `canvas_adapter_version`，消息插件保存 `presentation_plugin_version`。历史未固定版本的引用不自动重写。读取定义可给 `?version=...`，显式回退通过保存对应旧内容的新版本或选择旧版本引用完成；删除后历史版本保留但停止执行展示。写操作带独立 `revision`，冲突保留本地代码，刷新目录并核对最新定义后重试；归档项目只读。未保存代码关闭时会提示保留或放弃。

## API

所有接口使用现有平台认证及 `X-Project-ID`。写入请求包含目录的当前 `revision`。

| 接口 | 用途 |
| --- | --- |
| `GET /api/workflow-extensions` | 原生、平台与项目适配器目录 |
| `POST /api/workflow-extensions` | `{revision, definition, installed}` 创建项目适配器 |
| `GET /api/workflow-extensions/{id}` | 读取适配器完整定义 |
| `PUT /api/workflow-extensions/{id}` | `{revision, definition?, installed?}` 修改定义或安装状态 |
| `DELETE /api/workflow-extensions/{id}` | `{revision}` 删除适配器 |
| `GET /api/workflow-extensions/usage` | 当前流程组件引用 |
| `POST /api/workflow-extensions/expand` | `{component, raw_xml}` 返回展开图及目标节点 ID，不保存 |

此功能与[接口消息展示插件](interface-plugins.md)分别管理；消息插件解析 WebSocket 已有收发帧，画布适配器编辑 JMeter 组件属性。
