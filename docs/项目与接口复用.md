# 项目与接口复用

项目是 PressureCooker 的资源边界。接口集合、环境、流程、发布脚本、数据集、任务和报告均关联项目；切换项目会重新加载当前项目的数据。项目归档保留历史读取与下载，禁止新增或修改，不自动停止正在执行的任务。

## 从接口复用到流程

1. 在接口管理新增或导入集合，编辑请求参数、正文、认证及环境变量后保存。
2. 在流程编排选择 HTTP 或 WebSocket 请求节点，选择当前项目中的集合与请求。
3. 核对请求和变量，应用到流程，再保存草稿。
4. 发布不可变脚本，创建任务时选择脚本版本、环境、集群和数据集。

流程保存集合 ID、修订、请求路径和方法，以及应用时的执行参数快照。集合后续修改不会改变已有流程或发布脚本；更新流程时显式刷新引用，再核对和发布。解除引用保留当前参数。

环境的基础地址与变量由项目统一管理；集合可按环境 ID 覆盖自定义变量。`{{name}}` 转换到 JMeter 表达式时保留其含义，无法可靠转换的认证、上传或序列化形式会拒绝不完整转换。

## 导入与导出

| 来源 | 可导入内容 |
| --- | --- |
| cURL | HTTP 方法、地址、请求头、查询、正文及支持的认证；只解析文本 |
| Postman | Collection v2/v2.1、嵌套文件夹及支持的认证与变量 |
| Apifox | 导出的 OpenAPI 3.0/3.1 或 Postman 内容 |
| OpenAPI | 3.0/3.1 JSON/YAML、模型、样例及扩展字段 |

集合可导出 OpenAPI 或 Postman。扩展配置能否被其他产品读取取决于接收产品；导出文件应随对应项目版本保存。流程支持导入/导出 JMX，未知插件保持原始 XML，发布脚本始终不可变。

## MCP 与 CLI

先调用 `list_projects` 或 `create_project` 获取项目标识，再为资源工具明确传入 `projectId`。流程、集合及环境写入需提供当前 revision；冲突后读取最新内容核对，不能覆盖他人修改。

| 操作 | 工具 |
| --- | --- |
| 项目及环境 | `list_projects`、`get_project`、`update_project`、项目环境工具 |
| 集合及请求 | `list_api_collections`、`import_api_collection`、`update_api_request`、`debug_api_request` |
| 流程及发布 | `create_workflow`、`preview_workflow`、`publish_workflow` |
| 脚本原文 | `upload_script`、`download_script` |
| 创建执行任务 | `submit_console_task` |
| 状态及停止 | `get_execution_status`、`get_execution_log`、`stop_execution` |
| 原始文件及报告 | `list_execution_artifacts`、结构化报告工具 |

`submit_console_task` 使用与控制台相同的队列。必须选择项目、集群、环境和具体发布脚本；省略 workers 时由平台固定所选集群的节点。每个节点执行完整 JMX，实际并发还取决于脚本参数。

```json
{
  "projectId": "project-example",
  "clusterId": "从集群列表返回的ID",
  "managerPlanId": "从发布结果返回的ID",
  "environmentId": "从环境列表返回的ID",
  "name": "示例任务",
  "properties": {"threads": "1", "loops": "1"},
  "idempotencyKey": "本次提交唯一且重试保持不变的键"
}
```

复制历史任务时先读取 `get_execution_copy_config`，核对旧环境快照与当前配置，再用新幂等键提交新任务。读取草稿、预览、发布、报告或工具目录不会自动执行压测；执行需要明确的任务提交。

完整 schema 和限制见 [MCP 接入](../controlplane/mcp-go/README.md)，页面 MCP 工具栏读取实际服务目录。CLI 使用相同 API，命令见 [部署与使用](部署与使用.md)。

## 备份与历史

数据库备份包含项目归属和内容版本；加密资源恢复依赖原 `session-key`。MCP 未发布草稿与 `draft-projects.json` 归属索引必须一起保留。MinIO 原件独立备份，恢复后按收据核验对象大小和 SHA256。

平台示例仅展示通用能力。真实业务接口、场景、准备器、协议校验、历史验收及发布回执由相应业务工作区维护，不是平台构建或常规测试的依赖。
