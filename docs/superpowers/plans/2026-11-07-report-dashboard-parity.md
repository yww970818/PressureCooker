# Report Dashboard Parity Implementation Plan

> For agentic workers: use executing-plans task by task; independent reporting, chart and page domains run in parallel under dispatching-parallel-agents. Preserve all existing collaborative work; no commits/staging of the untracked repository.

**Goal:** Implement all gaps identified against JMeter HTML, prioritizing measured concurrency, Latency/Connect, error statistics and step trends; deploy and verify using historical artifacts without business load.
**Architecture:** Extend the existing bounded streaming Go JTL parser and immutable reports; expose scoped analytics as a separate API. Vue renders reusable accessible interactive SVG charts, plus existing report management/node drilldown. Manager exports a self-contained escaped static HTML report without external assets/requests.
**Tech Stack:** Go/Vue existing dependencies only. No Java analysis service, no chart dependency. Current Go /private/tmp/jmeter-go-toolchain/go/bin/go.

## Constraints and choices

- User authorized all listed functionality and deployment. Use existing architecture and sensible defaults without a separate approval round. No true business pressure; local synthetic fixtures and historical reparse only. Preserve past receipts/runtime secrets; never print tokens.
- Existing API/metrics/node drilldown remain compatible. New parser version 1.3.0. Old reports have analytics detail_version0, reparse creates new version.
- Parser bounds persist. Add at most12000 total time aggregate points across all scopes, max512 distinct errors per scope, max128 response codes per scope; exceeding limits errors explicitly (old READY retained). Granularity configurable for reparse to fit longer runs (default1000ms). JTL original <=128MiB. JSON analytics max16MiB before DB publish (manager guard). Never average percentile summaries when filtering/zooming; zoom is view-only, report scope summary remains fixed.
- Global and node overall ordinary metrics exclude transaction records. Explicit sample_kind and native JMeter transaction responseMessage prefix identify transactions; avoid label heuristics. Unconfirmed scopes retain current warnings. TPS label is 事务采样/秒, never inferred business TPS from RPS.
- APDEX defaults satisfied500ms, tolerated1500ms; failed sample always frustrated. Configurable positive finite satisfied<=tolerated (both <=1e9) in immutable report analysis_options. The same options also contain granularity_ms integer1000..3600000. Backward defaults applied before identity hashing; include options in report identity but not source fingerprint. ParseOptions.AnalyticsOptions uses DashboardOptions.

## Frozen parser model

Analysis adds `Dashboard Dashboard` json dashboard. Public Go types may follow names below with standard Go capitalization; do not change JSON names without coordinating.

Dashboard: `{version:1,options:{apdex_satisfied_ms,apdex_tolerated_ms,granularity_ms},capabilities:{active_threads,latency,connect,response_codes,bytes,transactions},warnings:[],scopes:[]}`. Capability values AVAILABLE/PARTIAL/MISSING. Missing optional fields never invalidate otherwise valid rows, count warnings/missing and omit related numeric values. Zero is valid. Parser never stores raw requests or full URLs.

DashboardScope: `{node_id,step_key,label,sample_kind,metrics:<existing Metrics>,latency:<TimingStats>,connect:<TimingStats>,apdex:<Apdex>,points:[],distribution:[],percentiles:[],response_codes:[],errors:[],top_errors:[]}`. Four scope classes: global(node_id='',step_key=''), eachnode(node_id,step_key=''), eachstep(node_id='',step_key), node+step. Scope key/label exactly matches new existing Steps. Overall/node excludes transaction in ordinary stats but tracks transaction_count/point tps separately. Per transaction step metrics explicitly transaction_samples.

TimingStats: `{sample_count,mean_ms,min_ms,max_ms,p50_ms,p90_ms,p95_ms,p99_ms}`, nullable timings.
Apdex: `{score,satisfied,tolerated,frustrated,count,satisfied_ms,tolerated_ms}`; score null with no eligible samples.
DashboardPoint: `{timestamp_ms,width_ms,sample_count,success_count,failure_count,transaction_count,rps,success_rps,failure_rps,tps,mean_ms,p50_ms,p90_ms,p95_ms,p99_ms,successful_p90_ms,successful_p95_ms,successful_p99_ms,latency_mean_ms,latency_p95_ms,connect_mean_ms,connect_p95_ms,active_threads,threads_observed_nodes,threads_expected_nodes,bytes_received_per_second,bytes_sent_per_second,response_codes:[]}`. All optional metrics null when unavailable; rate denominators bucket width seconds. Response code item `{code,count,percent,rps}` (percent scope totals for scope; bucket totals for point).
- Active threads uses **latest timestamp valid allThreads per observed worker within bucket**, summed once per worker (never sum each sample/step repeated values, never sum per-node maxima from different instants). Label “活跃线程（采样观测）”; coverage counts exposed, partial buckets not claimed whole-cluster exact concurrency. No interpolation or configured thread fallback; step-scoped thread values only observed when this step sampled. allThreads absent means unavailable, do not use grpThreads as cluster total.
- Latency uses JTL Latency/latency; Connect uses Connect/connect/connectTime; allThreads valid nonnegative int. For samplers that do not support network timings, explain zeros/scope in UI, don't diagnose backend latency by subtracting these timings.
Distribution item `{lower_ms,upper_ms,count}`; bounded meaningful histogram including tail, show original interval labels. Percentile item `{percentile,value_ms}` from0..100 or1..99+endpoints, deterministic existing bounded histogram estimator.
Error item `{category,code,message,count,percent_total,percent_errors}`. Aggregate **all eligible failed JTL records**, independent of existing500 Issue storage cap; global/node exclude transaction rows consistently with ordinary sample_count/failure_count, pertransaction step scopes include their typed records; no worker/controller log events in request error denominator. Redact messages/codes before persistence; top_errors exact first5 count descending deterministic tie. Prefer failure/assertion text, fallback responseMessage/responseCode. Distinct overflow explicit; no silent Top5 error sampling.

## Frozen manager HTTP

- GET `/api/pressure-reports/:id/analytics?node_id=&step_key=` -> `{detail_version:1,options,capabilities,warnings,nodes:[<existing report node objects>],steps:[{step_key,label,sample_kind}],scope:<matching DashboardScope|null>,series:[<step scopes for selected node, or selected step only>]}`. No node=>global. Allsteps=>ordinary/tx typed series separated by sample_kind. Unknown scope returns scope:null emptyseries with valid catalog; not fabricated. Legacy0 response with empty scope/catalog.
- GET `/api/pressure-reports/:id/export.html` authentication+project enforced; download escaped self-contained HTML with no external assets or network. Exports all collected analytics, summaries, errors, node evidence metadata and bounded redacted log text. Response Content-Disposition safe fixed filename. Default report/detail/latest/compare must not ship the large dashboard/scopes or node_logs; separate API loads lazily. Exports immutable full report, not client zoom.
- POST generate body existing + optional `analysis_options:{apdex_satisfied_ms,apdex_tolerated_ms,granularity_ms}`. Store normalized snapshot; pressure work passes reporting.ParseOptions.AnalyticsOptions. ID identity includes normalized options; changing options same idempotency key conflicts. Missing options on reparse inherit current report options (or default) chosen manager; frontend passes explicit options when editing settings.
- Store dashboard inside existing pressure_reports.data (no new table); dashboard/options hash version and immutable publication. Public report includes `analytics_version:1`, analysis_options. Time-series no extra SQL rows, max16MiB dashboard.
