# 逐功能审查与通用化清理 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 逐项审查当前所有平台功能，移除确认无用或业务定制的实现，修复可复现异常并验证。

**Architecture:** 沿用 Go 管理端/执行器/MCP、Vue 页面及既有模块化边界。按功能记录源码入口、检查结果、复现与验证；仅为已确认缺陷做必要的依赖或模块调整，保留通用协议及扩展模型。

**Tech Stack:** Go、Vue、MySQL、Redis、JMeter 官方运行时。

**Spec:** 本次用户逐功能完整检查、删除定制/无用代码并修复异常的要求；仓库规则见 `AGENTS.md`。

## Global Constraints

- 保留多人未提交修改。仓库无初始提交，使用 `runtime/baselines/20261109-full-feature-audit/` 源码快照和逐文件指纹复核，不创建包含他人改动的提交。
- 密钥及验收记录只在忽略的 runtime 内保存，不打印密钥。
- 不启动真实业务压测或真实业务长连接，不清空用户数据；只用自有隔离 SQL 前缀、Redis 端口与本地夹具。
- 节点状态以 Core 汇总为准，管理平台不得主动探测节点状态。
- 不删除官方依赖、通用协议兼容或用于证明不执行业务语义的反例测试；不改写历史发布清单和回执。
- RPC/gRPC/Protobuf 保留模型不冒充执行能力。业务自定义只能作为项目资源/插件，不在核心新增业务默认值。
- 若发布，必须从当前最终源码重新构建，并保留现存实例 Compose 标识、目录和持久卷；无新部署请求时先完成本地改动和验收记录。

## Review Focus

1. 项目切换、归档及并发修订不能串项目或覆盖新数据；跨项目失败必须可验证。
2. 空值、无效分页/规则/插件及不支持协议不能被静默解释成有效执行参数。
3. 请求取消、进程关闭和依赖短暂故障不能泄漏连接、任务租约或伪造就绪状态。
4. 已删除实现必须无有效调用、生成/嵌入入口或兼容用途；测试反例和历史运维标识分类保留。
5. 节点失联、观测陈旧和恢复必须保持 Core-only 与租约/代次/观测 epoch 栅栏。
