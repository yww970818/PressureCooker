# 集合环境继承项目环境实施计划

> **For agentic workers:** Use superpowers:subagent-driven-development for the cohesive implementation and independent review. Root owns integration and deployment.

**Goal:** 接口集合只引用项目环境列表及服务器地址，按项目环境 ID 保存集合自定义变量，运行时集合同名变量覆盖项目变量；删除项目环境联动清理集合当前配置。

**Architecture:** 复用现有项目环境 API、AES-GCM 集合存储与 revision/OCC。集合只存变量覆盖，项目环境的名称、地址、继承变量动态读取；调试、MCP 与引用接口的 JMeter 流程使用一致的合并规则。删除项目环境和清理该项目所有集合的对应覆盖处于同一事务，旧草稿或历史集合版本不能恢复已删除环境的覆盖。

**Tech Stack:** Vue 3 / Scalar / Go / MySQL / JMeter。

**Spec:** 本会话用户明确要求：集合环境继承项目环境列表、移除集合独立列表及服务器地址编辑、合并项目和集合自定义变量且集合优先；删除项目环境同时删除接口管理中该环境的配置值。

## Global Constraints

- 所有自研前端 Vue，服务及 MCP Go；不加服务、不改业务镜像、不接生产目标发压。
- 用户已授权本会话统一集成发布。工作区为共享未跟踪资产，不 git reset/clean/commit，不迁移或覆盖无关编辑；以源码 tar 基线复核。
- 保留主题、画布缩放、结构/源码预览、节点名称以及最新参数分类和流程标题布局。
- base_host 为项目环境保留项，集合无法覆盖其值。覆盖值允许空字符串，空值不能被误认为未配置。
- 按环境稳定 ID 关联，项目环境改名/更换地址/变量会动态反映；同名环境跨项目必须隔离，删除的 ID 不能重新写入当前集合配置。
- 新配置建议 `client_state.project_environment_overrides = { [environmentId]: {variables:[{name,value}]}}`，没有私有环境名称/地址副本。不写入浏览器持久存储；继续使用集合 AES-GCM、版本号、历史和导入导出。
- 集合环境页只有项目环境选择、继承内容说明/只读展示、自定义覆盖编辑；移除私有环境新建/重命名/删除及导入到项目入口。选择与请求调试共用项目环境状态。
- 浏览器直连、Master 转发、MCP debug 的变量合并规则相同：项目自定义变量→集合覆盖→受控本次显式调试覆盖（如保留原请求级能力）；base_host 最后锁定为项目服务器地址。
- 旧集合环境数据不批量破坏性删除；旧自定义变量须给出合理兼容处理，不能再以旧服务器地址/列表作为新界面的环境来源。同名迁移/无映射规则写入交付说明，不能静默把某环境值套给另一个环境。
- 引用接口的绑定流程不能把预览服务器或项目变量固化到 JMX；不同项目环境的集合覆盖须随任务所选环境生效，多节点/多集合相同 key 不可互相污染。不可变发布版本、运行快照与原始文件归档保持原义。
- 删除项目环境：同事务清理该项目所有当前接口集合中对应 ID 的覆盖值，保持加密、OCC 和版本记录一致。已提交任务和不可变历史版本不改写；从历史恢复/过期页面再保存不能复活被删除环境的配置。
- 只运行变更相关测试；测试夹具隔离 MySQL 表，实际请求仅用自有 Docker 内部目标。
