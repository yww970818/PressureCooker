# 事务与可观测性实施计划

**目标：** Redis 变慢时不占数据库事务/运行行锁；请求取消及时释放资源；健康与故障信息能反映实际状态并保持脱敏。

**设计：** 持久化 outbox 保持现有字段和 PENDING/PUBLISHED/CANCELLED/FAILED 状态。短事务领取时增加 attempts、将 next_attempt_at 设为领取期限，提交后在事务外发布；确认时核对领取版本并重查终态。失败退避，过期可重领，迟到发布通过执行器现有 task/attempt/租约检查避免重复执行。无新数据库列或外部依赖。

数据库封装增加带 Context 的同名方法，保留表前缀隔离；现有调用兼容。优先把列表请求、投递和诊断全链路绑定取消/超时。`/healthz` 保留存活含义；新增 `/readyz` 检查 MySQL、Redis 与控制循环进度。认证后的 `/api/diagnostics` 按项目返回积压、失败、数据库池及本进程投递计数。错误日志只记录受控分类、任务/尝试标识、请求关联 ID，不输出凭据、地址、属性或错误原文。

## 任务

- [x] 复现慢 Redis 阻塞停止、列表忽略取消、就绪检查与请求追踪缺失。
- [x] 实现短领取/确认事务、事务外发布和过期/迟到确认保护；验证取消后迟到消息不可执行、重试不丢任务。
- [x] 为数据库方法、领取/确认和列表查询传播 Context；验证表前缀、连接池等待与事务取消。
- [x] 实现循环进度、受控日志、请求 ID、就绪检查和按项目诊断；验证依赖故障、循环失联、超时及脱敏。
- [x] 运行管理端/执行器隔离测试及构建，独立只读复核，清理本任务临时容器，保留验收记录。

## 重点复核

网络调用期间不得保留数据库连接/锁；领取版本只能由当前持有者确认；取消可与发布并发但不能授权执行已终止任务；数据库取消和重试不能逃逸表前缀；存活不等于就绪；诊断按项目隔离且不回显地址、凭据或原始异常。请求关联 ID 由服务端生成，不信任来访值。索引/缓存及历史备份字段保持原有契约。
