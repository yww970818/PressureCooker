# 架构整理、协议扩展与项目插件计划

**目标：** 移除退役实现和 Python 工具依赖，沿用 Go 后端/Vue 前端；补齐项目级配置型、代码型消息插件；为 RPC、gRPC 和 Protobuf 保留明确模型及能力边界。

**基线：** 仓库尚无初始提交，现有文件由多人协作产生。当前源码快照及指纹已保存到忽略的 runtime 基线目录，按文件所有权集成，不重置他人改动或历史发布记录。

## 模块边界

- 运行与构建工具：有效 Python 工具迁到独立 Go 运维 CLI；删除过时 HTTP 故障验收脚本和内联 Python。官方 Node MCP、JMeter 和线程扩展继续使用官方运行时。
- 接口协议：纯协议注册/校验与实际 HTTP/WS 执行分开。RPC/gRPC/Protobuf 元数据可保存、预览和原文导出；当前无执行适配器时明确拒绝调用，不能回落成 HTTP。
- 项目插件：目录/定义/安装状态由 Go API 和 MCP 管理，采用独立 CAS 修订号；定义加密保存。新增、编辑、删除、导入、导出以及安装/卸载均按项目隔离。
- 配置型插件：受限 JSON 路径与字段映射，输出受控的消息展示结构。
- 代码型插件：上传 JavaScript 解析函数，仅在独立的 sandbox iframe + Worker 运行；禁止访问主页面、凭据和网络。限制输入、输出、时间；失败回退原文。插件不持有连接或发送能力。
- 数据库：新增007索引迁移，优化数据集列表和报告列表；报告分页加入唯一 ID 排序。用户已授权必要时清空测试业务数据；当前增量调整无需重置，沿用加密工作区、不可变版本和备份格式，不重写旧迁移。
