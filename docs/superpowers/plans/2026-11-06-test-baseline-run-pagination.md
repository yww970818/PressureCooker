# 测试基线与任务列表分页实施计划

> 使用 systematic-debugging、test-driven-development、executing-plans 逐项实施；用户已授权执行上一轮评审中的前两项。

**目标：** 恢复可信且可重复的测试基线，避免列表请求加载全部历史任务和逐条查询关联记录。

**设计：** 保持现有 Go/Vue 分层及 API 的 `items`、`total`、`project_id`、任务字段和 `limit/offset` 语义。SQL 按项目、状态及名称/ID/备注的大小写不敏感字面子串筛选，按创建时间及 ID 倒序分页，只解密本页任务；批量读取历史报告、Webhook 和投递状态并复用详情脱敏逻辑。新旧库均具备项目/状态/时间组合索引。

**方案取舍：** 在现有接口内下推查询，兼容 CLI/MCP 和历史脱敏断言；轻量摘要接口与游标分页留待后续单独版本化。本轮不改变执行租约、压测行为或部署配置。

**约束：** 保留协作中的未提交改动；当前源码未被 Git 跟踪，使用 runtime/verification 中的文件快照复核定向差异，不擅自提交整个工作区。集成测试仅使用临时本地容器、随机表前缀、模拟对象存储/agent 和假 JVM。
