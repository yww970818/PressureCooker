# PressureCooker 全页面性能与表结构优化

用户要求流程编排、压测报告及其他页面均避免卡顿；已确认按 5000 节点流程、100 万条原始请求的报告、1 万条任务历史验收。保留 Go/Vue/MySQL/JMeter/MinIO 体系、当前中文样式、项目隔离与全部历史数据。自研代码仍为 Go/Vue，不增加独立 reporter 服务，不运行真实业务压测。

## 实测与原因

home 当前流程列表 21,979,018 B，中位 4177.7 ms；1553 节点详情 8,420,495 B，中位1492.1 ms。计划列表523703 B/200ms，接口集合354142 B/181ms，环境1531 B/9.6ms，任务列表20条165138 B/149ms，报告列表20条11153 B/108ms。原始基线仅在 runtime 保存，不输出凭据。

workflows/api_collections 的列表直接选择、解密所有 payload。流程编辑多次 JSON 深拷贝、排序和全图序列化；LogicFlow 历史也携带组件源码。报告父记录重复包含 dashboard/日志/请求明细，分页筛选仍依赖 JSON_EXTRACT；READY 报告仍每5秒整份轮询。源码、结构及选择列表缺少统一的大数据渲染边界。

## 方案与取舍

采用现有 MySQL 的增量改造：小摘要与大详情分离、报告按查询范围落表、索引下推、前端按需加载和有界渲染。完全拆成新的编排领域数据库会改变发布、版本及变量作用域，迁移成本高；仅加内存缓存或提高容器额度不能解决大响应和全图重复处理。本轮采用增量方案，技术选择由实现方承担；用户已经授权优化并确认验收规模，沿用此前本会话统一集成发布的授权。

## 数据模型

1. 工作流、接口集合、版本及计划增加小摘要投影。工作区摘要保持 AES-GCM 加密；摘要不得含 graph、OpenAPI document、Cookie/token、环境变量值或数据文件内容。当前记录和对应历史版本在同一事务更新投影，revision 对齐。新增项目/删除/更新时间复合索引及计划名称/版本检索索引。旧数据有可恢复的分批回填，未回填记录不得消失；旧完整读取接口和不可变快照保持可用。
2. CSV 节点建立 workflow_csv_nodes 读模型，按 project/workflow/revision/node 稳定关联，存储列定义及节点说明，不存数据内容。数据集列表/目录和脚本关联名称走摘要/节点投影，避免加载整份画布及逐节点查询。
3. 报告增加轻量 summary_data，供列表、状态、对比及页面概览使用；任务页读取摘要而非复制所有运行快照和报告详情。明细继续保留，但页内只读取当前页。
4. 步骤、问题、日志等常用筛选投影 node/step 字段并建匹配索引；超长节点标识用稳定哈希索引并校验原值，不截断或改变统计口径。
5. dashboard 按 report/project/node/step/sample_kind 保存独立范围记录，摘要和范围目录独立读取。切换节点/接口只取所选范围；避免每次解析整个 dashboard，也不先序列化整份大 dashboard 再判断大小。统计值与分位数保持原算法，图形抽稀不能改变指标或原始证据。旧报告读取有兼容和回填路径，显式完整导出可重建，页面读取必须有界。
6. 派生的不可变计划图预览可按 plan SHA/预览格式版本缓存并压缩，保留项目校验且只从对应 JMX 快照派生；不以当前草稿冒充历史版本。

## 页面与接口

- 列表增加摘要视图、分页/搜索，前端和 MCP 按用途选择摘要与详情；兼容旧调用时不得向页面继续传整库 graph/document。创建任务在选中计划后才获取 CSV 要求等详情，保留复制任务的完整参数和过期数据提示。
- 大 JSON/源码的解析、格式化和序列化可移至 Web Worker；有取消、项目切换和旧响应丢弃机制。缺少 Worker 的测试/环境有兼容路径。
- 画布只放绘制信息和轻量 payload 引用，组件源码与配置由不可变快照保存，撤销/重做必须恢复对应配置。变更标记采用可恢复的版本/增量签名，不能每次拖动都对整份源码序列化，也不能靠可能碰撞的短哈希忽略编辑。
- 源码、结构、长列表和下拉菜单按可视区域渲染；按需挂载详情。折线保留图例、刻度和节点 tooltip，避免每个点都创建常驻 DOM，最近点查找避免线性扫描。
- READY/FAILED 报告停止整份轮询，隐藏页面不重复刷新，切换时取消过期请求；准备状态只轮询小摘要。
- 对合适的 JSON/XML 页面响应启用流式 gzip，不缓存或改写目标调试、WS、SSE、原始文件下载和鉴权行为。

## 迁移与验收

迁移只增加列/表/索引，不改写旧迁移指纹，不删除原 payload、版本、MinIO 对象或 JMX；投影回填需可重试且不覆盖并发新版本。备份/恢复原数据之后能够重建派生读模型。继续保留其他会话改动，不创建整个未跟踪仓库的初始提交。

目标为当前 home 服务与约定测试设备上的列表/搜索/翻页 API P95≤1秒，常用列表中位≤500ms；页面加载期间仍能响应输入，大画布拖动/缩放/选择以及图表 hover 的已加载交互处理目标≤50ms。冷启动迁移/第一次构建缓存与暖态分别记录，不能用缓存掩盖查询错误；不承诺任意设备或无限数据量绝不卡顿。

用隔离数据库与随机表前缀验证升级、回填重入、并发保存、跨项目访问、撤销与未保存编辑、历史源码指纹、数字精度和分页。用无网络合成数据覆盖5000节点、100万JTL、1万任务；浏览器验证各页面和关键交互，输出真实前后数据。发布后检查健康与只读页面，不创建业务压测任务。

## 复核后的验收与回退约定

参考浏览器使用本机 Chromium、1440×900、100%缩放；同一设备和网络分别记录前后结果，浏览器具体版本及硬件记入运行记录。百万条JTL基准固定6节点、200个步骤、15分钟时间窗、90%成功/9%HTTP失败/1%超时，另测边界与高步骤数；原始统计值可预先计算，不启动业务流量。图规模5000节点/4999边，不要求每个节点都是不同接口；5000节点与百万请求不是无限步骤维度的承诺。发现现有500步骤/4096节点步骤组合限制时必须单独记录，不能无条件提高导致内存失控；若真实完整套件超限则随本轮存储改造定向验证调整。
