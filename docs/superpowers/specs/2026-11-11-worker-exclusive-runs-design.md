# 多批任务与 worker 独占

用户要求平台全局支持多批任务同时运行，每个 worker 同时只能用于一个任务；提交时任何所选 worker 已被占用则拒绝创建。

采用现有事务与租约的最小扩展：提交与领取在已有集群配置锁下检查全项目 worker 交集；QUEUED、PREPARING、RUNNING、STOPPING、RECOVERING 均占用 worker。进入上传/回调阶段表示执行与清理已结束，可以再次使用。幂等重放在占用检查前返回原任务。

预占只统计当前 Redis 执行协议任务，退役协议历史记录继续只读，不代表真实 worker 占用。领取只检查物理执行状态；升级前已存在的重叠队列由 worker 租约逐个执行，不能因相互排队而死锁。故障恢复每 tick 处理一项并轮换候选，单个失联 worker 不会让其他 worker 的恢复一直等待。

只做前端检查无法阻止并发提交；只删除全局 SQL 限制仍会被全局 Redis 租约与 Core 串行执行阻塞。实现同时覆盖管理端、Redis worker 集合租约、Core 并行执行和创建页面。租约原子获得整组选中 worker，续租与释放检查原持有人；旧全局租约继续与新租约互斥。恢复仍以当前租约 epoch 的 Core 上报及 worker 空闲证据为准。

同一 Core 内任务拥有独立执行状态、停止端口与 Linux JVM 身份，清理一个任务不能终止另一个任务。worker 本地仍只接收一个分配，prepare 必须验证租约覆盖自身。

界面显示已占用 worker，已选节点变为占用时阻止提交，服务端最终校验返回 409/worker_busy。占用信息只披露 worker 标识，不泄露其他项目任务内容。

保持通用 Go/Vue 架构，不增加业务逻辑，不运行真实业务压测，不修改线上对象，不自动提交或部署。验证使用通用单元测试、本机隔离依赖和前端构建。
