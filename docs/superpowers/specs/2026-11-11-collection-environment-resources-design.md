# 集合环境独立管理与项目环境页面调整

状态：2026-11-11 用户要求“出详细设计，并实施部署”，按本设计进入实施与部署。执行中未明确的实现细节由实现者依据本文作出并记录判断，不再重复询问。

## 目标与已确认要求

本次调整让接口管理以集合环境作为唯一可选择的调试环境，项目环境作为可选的继承来源。

用户明确要求：

- 项目环境页铺满可用工作区。
- 集合环境管理页面放在项目环境页，统一维护两类环境。
- 接口管理移除“项目环境”和“集合环境”选项卡，只保留调试使用的集合环境选择器。
- 集合环境支持新增、查看、修改、删除。
- 新增集合环境可以选择一个项目环境作为父环境。
- 接口管理的环境选择器只列当前集合的集合环境。
- 用户已选择持续继承：父环境的地址和变量更新后，未覆盖项随之更新；集合同名配置优先。
- 用户已确认流程编排一起调整，接口调试和流程引用共用集合环境。

“父集合”按上下文解释为“父项目环境”。继续使用 Vue、Go、现有加密集合存储和 revision 冲突控制。

## 现状与影响范围

目前集合仅保存 `client_state.project_environment_overrides[projectEnvironmentId].variables`，没有独立的集合环境身份、名称或地址。接口管理顶部选择器直接使用项目环境列表；HTTP、WebSocket 和预留协议编辑器共用该模型。

项目环境页面自身存在 `max-width:1100px`，外层工作区也有限宽。接口管理内嵌了同一项目环境编辑器，形成第二个维护入口。

流程与已发布脚本依赖集合精确修订和项目环境 ID；任务提交固定环境快照。新模型必须兼容这些历史引用，不能因页面改动改变已发布内容或历史任务。

## 方案选择

1. **独立集合环境，持续继承项目环境。** 集合环境有自己的 ID、名称和配置，可关联一个父项目环境；运行时合并。用户已选择此方案。
2. **新增时复制项目环境。** 实现简单，但之后不会跟随父环境更新，与用户选择不符。
3. **继续直接展示所有项目环境，只修改界面名称。** 保留现有模型，但无法实现集合环境独立增删改查，也无法满足只选择集合环境的要求。

实现建议：集合环境作为集合内容的一部分保存，共享集合的加密、revision、历史与导入导出；暂不增加数据库表和独立版本体系。

## 页面与交互

### 项目环境页

- 保留全局侧栏、顶部导航和页面标题，“全屏”解释为填满剩余内容区，不进入浏览器全屏模式。
- 移除项目环境卡片和该页面外层的固定最大宽度限制，桌面端使用可用宽度与剩余高度。
- 内容较多时在编辑区域内滚动；窄屏恢复自然纵向布局。
- 保留现有增删改查、未保存修改保护、归档只读、变量生成规则和失败重试行为。
- 在同一页面设置“项目环境”“集合环境”两个管理分区；建议使用两个页内选项卡，左侧导航仍为“项目环境”。
- 集合环境分区先选择当前项目下的接口集合，再管理该集合的环境；集合列表、环境列表和编辑区使用剩余可用空间，显示当前环境的所属集合。
- 从接口管理进入时可定位到当前集合的集合环境分区。页面记忆只保存分区、集合 ID 和环境 ID。
- 任一分区有未保存修改时，切换分区、集合或项目遵守现有保存/放弃/取消机制，不丢弃草稿。

### 接口管理

- 移除环境配置相关选项卡及内嵌的两类环境编辑器；只有一个调试内容分区时不保留空的单项选项卡栏。
- 移除内嵌环境编辑器的保存、脏状态和忙碌状态关联；环境配置在项目环境页保存，接口管理自身仍保存请求定义。
- 旧页面记忆中的 `project-environment` 或 `environment` 回退到“请求调试”。
- 请求页环境选择器改为当前集合专属选择器；切换集合时恢复各自的集合环境选择，不复用项目环境选择状态。
- 没有集合环境时显示“请先创建集合环境”，提供“管理集合环境”入口，跳转到项目环境页并定位当前集合；不自动选择父项目环境发送请求。
- 在项目环境页保存后更新共享集合环境状态；接口管理重新进入或刷新时获取最新已保存的配置。请求定义的未保存草稿不被环境管理回执整份覆盖。
- 请求发送仍由原来的发送、连接、发送消息按钮触发。

### 集合环境编辑

- 此编辑器只出现在项目环境页的集合环境管理分区；接口管理及流程引用弹窗只提供环境选择和生效值预览。
- 环境列表展示名称、父项目环境名称或“独立环境”、可用状态。
- 支持新增、重命名、编辑、删除和查看最终生效配置；同一集合内名称唯一，不同集合互不影响。
- 新增字段：环境名称、可选父项目环境、基础地址、自定义变量。
- 选择父环境时显示继承地址与变量，以及每项的来源；自定义变量可覆盖、增加或恢复继承。
- 空字符串是普通变量的有效覆盖，删除覆盖项才恢复继承。
- 保存随当前集合提交，沿用集合 revision；保存失败保留所有草稿和选择。
- 删除集合环境显示确认；删除已选环境后清空选择，不自动切到其他目标。
- 归档项目只读。

## 由实现者提出、待一并确认的默认规则

1. **无父环境可独立创建。** 必须填写有效 HTTP(S) `base_host`，自定义变量全部由集合自己维护。
2. **基础地址也允许显式覆盖。** 有父环境时默认继承，可切换为集合自定义地址；恢复继承后继续跟随父环境。不能把空字符串作为最终基础地址。此规则扩展了旧模型中“集合不能改 base_host”的约束，需在设计确认后同步修改文档及校验。
3. **同一父环境可以派生多个集合环境。** 例如同一测试环境下的两组认证配置；通过各自 ID 精确选择。
4. **父环境删除不级联删除集合环境。** 保留名称和自有配置，标记父环境失效，阻止新的调试；用户可以改选父环境或解除继承并补齐独立配置。不会自动复制被删除父环境的秘密值。
5. **流程节点显式绑定集合环境。** 新引用在节点中保存集合环境 ID；任务页的项目环境继续服务未绑定新集合环境的节点，不替换已明确选择的集合环境。任务提交前展示这些节点的目标来源与最终地址，避免选择任务项目环境后误以为所有节点都已切换。该执行规则是实现建议，待用户随本设计一并确认。
6. **全部目标已明确绑定时不要求无用途的项目环境。** 管理端能确认所有启用的 HTTP/WS 请求均有新集合环境绑定，且其余配置没有项目环境依赖时，任务可省略项目环境。旧脚本、存在未绑定请求或无法确定依赖的扩展脚本，保持原来的项目环境必填规则。此判断由发布脚本元数据决定，不由客户端自行声明。
7. **解除接口引用默认保留环境绑定。** 接口定义来源和集合环境来源分别存储；解除接口引用只解除定义关联。另提供显式解除环境绑定操作：流程已启用项目环境绑定时回到任务项目环境，否则保留作者编写的占位符并要求用户手工补齐固定配置，未补齐不能发布，不自动把当前秘密值或地址写进脚本。

## 数据与解析契约

建议新增：

```json
{
  "client_state": {
    "collection_environments": [
      {
        "id": "collection-env-stable-id",
        "name": "测试账号组 A",
        "parent_environment_id": "project-env-stable-id",
        "variables": [{"name": "credential", "value": "example-value"}]
      }
    ]
  }
}
```

- `id` 是集合内稳定身份，独立于父项目环境 ID；创建时由管理端产生。父环境改名不改变绑定。
- `parent_environment_id` 可缺省，只能引用当前项目的有效项目环境。
- `base_host` 是可选的环境顶层字段；父环境存在且该字段缺省时继承，显式提供时须为有效完整 HTTP(S) 地址。无父环境必须提供。
- `variables` 只保存自有变量与覆盖，不复制父环境变量；禁止把 `base_host` 混入普通变量列表。
- 保存配置不解析生成规则；未知规则按现有惰性兼容契约保留，执行时校验。
- 数量、变量名、长度及规则校验复用现有通用限制，不增加业务默认值。
- 未变化的旧失效父引用可保留并保存其他字段；新增或改选父环境时必须验证项目归属及有效性。读取未知或失效引用不能阻止保存整个集合。
- 项目环境与集合环境的选择状态相互独立；浏览器持久状态只保存 ID 和页面状态，不保存地址、变量或秘密值。

调试解析顺序：

```text
父项目环境的当前配置（可选）
  → 集合环境自己的基础地址与变量覆盖
  → 本次 API/MCP 显式变量（如有，仅普通变量）
  → 解析生成规则并固定本次操作的值
  → 替换当前接口模板并发送
```

`base_host` 由集合环境的最终地址决定，单次变量不能替换它。返回脱敏来源：集合 ID、集合 revision、集合环境 ID，以及存在时的父环境 ID、revision。浏览器 HTTP 直连、Master 转发、WebSocket 使用同一合并规则。

## 流程引用与任务执行

- HTTP 和 WebSocket 引用选择当前项目的集合、接口和该集合下的集合环境。环境列表与接口管理共用解析和可用性规则；弹窗不嵌入环境管理页面。
- 接口定义来源继续存于节点 `api_reference`，含 `collection_id`、精确集合 `revision`、`path`、`method`；另保存 `collection_environment_reference={collection_id,revision,collection_environment_id}` 及请求模板快照。新绑定最初与接口来源使用相同集合和修订。引用集合历史版本时，从同一版本读取集合环境定义，不把当前最新环境覆盖套到旧引用。
- 应用、编译和发布只保存模板、身份与来源，不将预览环境的地址、认证值或随机生成值写入 JMX。
- 新绑定具有节点级语义：同一流程的不同引用节点可以选择不同集合环境；普通项目环境绑定仍作用于没有新集合环境绑定的节点。
- 新绑定地址和变量通过节点隔离的运行属性注入。HTTP 的协议、主机、端口和基础路径均使用对应节点的环境；WS 的地址、握手地址和消息模板从同一有效环境解析。不能只替换普通变量却继续使用全局项目地址。
- 创建任务时，按精确集合修订及集合环境 ID 读取自有配置，再读取当时父项目环境的有效修订，生成并冻结节点级完整环境快照。父环境必须存在、有效且属于当前项目；失效则拒绝新任务并定位到具体节点。
- 静态普通变量合并顺序为父项目环境变量 → 任务显式普通属性（如有）→ 集合环境自有覆盖；最终地址由集合环境定义。CSV、前序提取器及 WS 自动变量仍遵守现有作用域和动态生产者优先规则。
- 接口管理修改集合环境后，流程须显式刷新引用、保存并重新发布才采用新的集合自有配置；父项目环境的未覆盖项持续继承，在新任务提交时取当时配置。已提交任务和幂等重试复用冻结快照。
- 新引用已绑定的集合环境在当前集合删除后，历史引用仍使用其精确修订定义；其父项目环境若失效则阻止新任务。已有任务继续使用快照。
- 保留没有 `collection_environment_reference` 的旧引用执行语义，按原集合修订和项目环境覆盖解析，不猜测映射到某个新集合环境。刷新旧引用时必须由用户显式选择集合环境，未刷新不改写历史行为。
- 解除接口引用保留请求模板快照和独立的集合环境来源；环境选择及来源预览继续显示。显式解除环境绑定的结果遵循上述默认规则，确认界面明确说明新的目标来源，不静默切换，不自动冻结当前值。
- 刷新接口引用时同步检查原集合环境 ID 在目标集合修订中是否仍存在；存在则明确展示并确认采用新修订，不存在则要求重新选择。不得从同名环境推测替代项。仅修改接口方法或正文不自动刷新环境修订。
- 管理端在发布时计算并返回是否仍需要任务项目环境。任务页/API/MCP 仅在该元数据明确允许时接受省略；无项目环境的任务仍须冻结各节点的集合环境及父环境快照，并支持参数摘要、幂等重试和任务复制。
- 任务预览、参数摘要、历史和复制任务包含节点、集合、集合修订、集合环境和父环境来源及脱敏后的最终参数。复制使用历史快照与使用当前配置沿用现有显式选择，不混合两种来源。

## API 与 MCP

- 新增当前项目、当前集合下的集合环境 CRUD 路由，可使用 `/api/api-collections/:id/collection-environments` 及子资源路径，避免混淆旧 `/environments` 的项目环境覆盖契约。
- 写操作必须携带当前集合 revision，成功返回更新后的集合或足够的完整回执；冲突返回 409，不覆盖其他页面的修改。
- 调试增加明确的 `collection_environment_id` 目标选择；按集合 ID 验证归属，禁止拿其他集合或其他项目的环境 ID 执行。
- 新入口不能依靠名称、活动旧环境或父项目环境 ID 猜测集合环境。
- 旧项目环境调试 API/MCP 保持显式兼容，使用原有 target_source 契约；它不出现在接口管理的新选择器里。不可同时传入新集合环境与旧项目/文档目标参数。
- MCP 增加对应集合环境 CRUD 和调试参数说明；旧 `set_api_environments` 保留原含义，避免把同一参数静默改成另一种身份。
- 流程 MCP 的图结构、校验、预览与发布支持新引用字段；提交任务返回冻结的集合环境来源，重试继续使用原幂等标识及快照。
- 新 MCP 工具权限、归档限制、加密存储和返回脱敏遵循现有通用机制。

## 兼容与数据保留

- 不批量重写现有集合、历史版本、任务快照和发布 JMX，不启动真实业务压测。
- 未设置新 `collection_environments` 字段的旧集合，可以将已有、显式保存的 `project_environment_overrides` 条目投影为“旧配置兼容”的集合环境。只投影已有覆盖条目，不把所有项目环境自动加入集合。
- 兼容条目的 ID 必须确定且稳定，与新建 ID 使用不同命名域；按原项目环境 ID 动态继承，并保留其已有变量覆盖。
- 首次显式保存集合环境时，将当前兼容列表和用户修改一起保存到新字段；新字段存在后以它为权威，包括空数组。删除不会因旧覆盖条目仍存在而重新出现。
- 旧 `project_environment_overrides` 原文继续保留，供旧引用、兼容 API 和历史读取；新集合环境 CRUD 不擅自修改其内容。
- 更早的 Scalar 命名环境原文继续保留，不按名称猜测项目环境关联，也不自动成为可执行集合环境。
- 导入导出保留新旧字段；新父引用跨项目或不存在时保留配置并标记不可执行，允许用户修正，不读取其他项目资源。

## 实现涉及位置

- 前端：`Workspace.vue`、项目环境页及集合环境管理分区和样式；`ApiManagement.vue` 移除配置选项卡并接入专属选择器；HTTP/WS/预留协议编辑器、变量解析、页面选择记忆；流程引用编辑器、任务目标预览与参数摘要。
- 管理端：集合内容校验及历史保存、集合环境 CRUD、项目父环境解析、调试目标验证与来源信息；流程引用元数据、HTTP/WS 编译、节点隔离运行属性、任务快照与复制。
- MCP：新集合环境工具及转发、调试 schema、中文工具目录与工具文档。
- 文档：README、接口与流程使用说明、MCP 使用说明，明确接口管理与任务执行环境的区别。

## 验收

1. 项目环境页在宽屏填满内容区；小屏不产生横向溢出，长表格可操作。
2. 项目环境页同时提供两类环境管理；选择集合后可管理其集合环境。接口管理没有项目环境或集合环境配置选项卡，选择器仅列当前集合的环境；管理入口跳转到正确集合，空集合不能自动使用项目环境发送。
3. 创建独立环境与带父环境的环境，验证增删改查、刷新恢复、切换集合隔离、名称与 ID 的稳定性。
4. 父环境改名、改地址、增删改变量后，未覆盖项更新，覆盖项保持；清除覆盖与空字符串行为不同。
5. 验证自定义地址和恢复继承；父环境删除后保留集合环境并阻止调试，不自动换目标。
6. HTTP、WS 的环境解析、直连与 Master 转发保持一致；生成值不会回写到保存的配置。
