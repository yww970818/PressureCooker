# 流程画布与接口管理

登录 PressureCooker 后先选择项目，再进入“流程编排”“接口管理”“扩展管理”或“项目环境”。页面使用 Vue、LogicFlow 和 Scalar；保存、预览或发布资源不会自动提交压测任务。

## 流程工作区

工作区按脚本和草稿管理内容版本，支持流程预览、JMeter 父子结构、JMX 源码和版本记录。选择历史版本时读取其对应的精确 JMX；点击“编辑流程”直接复用当前精确版本的预览进入本地编辑，不创建副本、不等待重新导入。只有实际修改名称、说明、节点参数或布局后，点击保存或发布才创建草稿并记录原脚本来源；只查看、取消编辑或撤销全部修改不会生成副本。发布产生新的不可变脚本。

进入草稿或点击“编辑流程”时，先展示节点名称、类型、位置和连线，不自动选中节点；点击节点后再读取该节点的完整参数。HTTP 节点会同时读取直接关联的请求头和变量，读取失败可重试。详情固定读取打开时的版本，读取本身不会产生未保存修改。保存、源码预览或导出前自动补齐未打开节点，合并当前编辑内容；补齐失败则保留修改，不提交不完整流程。

新建流程或导入 JMX → 编辑节点及参数 → 保存草稿 → 预览编译结果 → 发布脚本 → 在任务页明确提交执行。草稿源码预览使用当前画布的临时编译结果，不隐式保存或发布。

连线表示父子作用域，同级顺序决定组件的执行顺序；拖动只改变布局。支持当前锁定 JMeter 5.6.3 的 117 种原生组件及平台 WebSocket。常用组件使用专用表单，其他组件使用通用属性树；自定义组件可提供 JavaScript 画布适配器。扩展管理显示每个组件来源和当前流程引用，详见 [JMeter 扩展管理](流程扩展管理.md)。未知插件连同子树保留原始 XML，安装适配器后须在节点明确选择。

HTTP 请求可以引用当前项目的接口集合及精确修订。引用保存请求参数快照和来源；集合更新后需显式刷新引用，再保存和发布。解除引用保留已应用参数。校验覆盖唯一根、父级、环、孤立节点、顺序和作用域；版本冲突保留本地修改供核对。

## 接口集合与调试

新建集合或导入 OpenAPI JSON/YAML、Postman、Apifox 导出或 cURL 文本，在 Scalar 中维护地址、方法、请求头、参数、正文及认证后保存。cURL 只解析文本，不执行 shell 命令；不支持或无法保真转换的内容会明确拒绝。

| 请求模式 | 网络来源 | 适用条件 |
| --- | --- | --- |
| 浏览器直连 | 当前浏览器 | 当前电脑可达目标，目标允许所需跨域请求 |
| Master 转发 | 部署的管理端 | 管理端可达目标，并通过平台鉴权及目标限制 |

单次调试由页面显式发送，不进入压测队列。管理平台认证和目标自身的认证分别处理。HTTP 转发限制、超时及响应大小以当前管理端实现为准；不会自动跟随重定向或把目标 Cookie 写入平台登录会话。

WebSocket 调试提供通用连接、发送、接收、JSON/文本匹配、心跳和关闭。业务字段通过显式消息模板、匹配规则和提取器配置。平台不内置某个项目的登录、审核、客服或机器人协议。消息展示插件由项目自行创建和安装，见 [接口插件](interface-plugins.md)。

响应提取规则可设置“选项名称路径”（`label_path`），从最终候选读取中文名称等展示文本；输出变量仍按原路径提取。数组候选保留响应中的顺序和原始序号，经过筛选也不重新编号。关联输出随同一个选项一起回填，避免名称和标识混配。

填写消息正文和模板名称后，点击“保存为模板”会将模板及当前集合的修改一并保存到服务端，刷新页面后仍可使用。同名模板会更新正文；保存失败会显示错误并保留名称、正文和未保存修改，可修正后重试。删除模板后仍需点击“保存集合”。

## 环境与变量

在“项目环境”创建不同测试环境。`base_host` 为必填 HTTP(S) 基础地址，支持端口和基础路径，例如 `https://example.test:8443/service`；其他地址及认证数据使用自定义变量。`url`、`baseURL`、`基础地址` 等名称都只是普通变量，不用于推断服务器地址；编辑器只采用显式 `base_host` 或导入文档中明确声明的 HTTP(S) server 建立地址草稿，保存时仍须校验。接口模板使用 `{{name}}`，流程/JMeter 使用 `${name}` 或运行属性引用。

| 使用位置 | 环境选择用途 |
| --- | --- |
| 接口管理 | 本次调试的目标地址与变量 |
| 流程编排 | 编辑和预览，不决定未来任务的执行环境 |
| 新建任务 | 固定本次执行环境的版本和完整快照 |
| 任务历史 | 展示提交时的快照，不随环境后续修改而改变 |

新流程默认支持项目环境绑定。已有固定地址脚本需要显式启用绑定并重新发布，历史版本保持原样。绑定脚本保存变量名和运行属性引用，预览环境的具体值不应写进发布内容。

集合变量按项目环境 ID 保存覆盖；同名集合覆盖优先，未配置时继承项目变量，空字符串也是明确覆盖。`base_host` 由项目环境统一提供。删除环境会清理当前集合中的对应覆盖，但不改写任务快照和历史发布内容。

未知生成器名称的完整变量规则会原样保存，并标记为不支持；执行前须替换为支持的规则、固定值或显式清除。读取和保存不会执行未知规则，运行解析仍会拒绝它。已有规则的非法参数、嵌入式或不完整声明仍禁止保存。

CSV 节点通过数据集绑定提供逐记录变量。JSON 提取器产生的变量遵循其执行作用域；不能依靠名称相同自动把一个节点的提取值当成其他并行作用域的输出。执行前核对 CSV 列、变量名称、引用关系及 copy/shard 分配。

## 脚本身份声明

身份名称、用途、必填项与字段类型来自不可变脚本。流程根 `TestPlan` 的 `properties.script_identities` 编译为 JMX 的 `pressurecooker.script_identities` JSON 字符串属性：

```json
{"schema_version":1,"identities":[{"name":"client","label":"客户端","purpose":"发送请求并核对响应","required":true,"fields":[{"name":"user_id","type":"string","secret":false,"required":true},{"name":"credential","type":"string","secret":true,"required":false},{"name":"enabled","type":"boolean","secret":false,"required":false}]}]}
```

字段类型为 `string`、`number` 或 `boolean`，均须明确 `secret`、`required`。可选身份可整组留空；有值时校验其必填字段。提交属性为 `script_identity.<身份名>.<字段名>`，脚本自行读取；平台不实现登录、Token 提取或账号顺序。最多20条身份、每条20字段；值不超过4096字符且为单行文本，number 必须有限，boolean 仅接受 `true/false`。任务全局属性最多100项。所有身份属性按敏感内容脱敏，`secret=false` 也不会使历史任务响应暴露它。

旧 `jmeter.cookie_accounts` 和 `cookie_account.*` 只保留历史读取，不再执行。CLI `convert-script-identities SOURCE.jmx NEW.jmx` 生成新的独立文件，输出新旧指纹且不覆盖目标；核对字段类型、秘密标记及文本替换结果后显式上传为新脚本。原 JMX、已冻结任务和指纹保持原样。转换不能替代业务脚本核对，不根据历史凭据补齐身份。

## 接口调试目标

集合调试 API/MCP 必须明确 `target_source`。`project_environment` 同时提供 `environment_id`，地址及变量依次来自项目环境、集合覆盖和单次变量；`document_server` 明确使用文档服务地址及单次变量，禁止同时传环境 ID。返回 `target` 含脱敏来源、集合修订与环境修订。旧 `environment` 参数被拒绝；导入的 Scalar 活动环境字段保持原文，不能隐式改变执行目标。页面项目环境选择与发送代理使用同一环境模型。

## 保存、鉴权与备份

集合、流程及修订使用项目隔离、认证访问和 revision 冲突检查。完整内容加密存入 MySQL，列表仅返回必要元数据；导出包含所选内容及其配置，需按项目数据处理。

备份需要同时保留数据库、发布内容、对象存储、MCP 草稿及归属索引。原 `session-key` 必须单独安全保存，快照本身不包含凭据文件。部署及恢复见 [部署与使用](部署与使用.md)，MCP 操作见 [项目与接口复用](项目与接口复用.md)。
